# GL-08: bounded same-file context

Session date: 2026-09-17 America/New_York. Runtime model: `gpt-5.6-luna` at the OpenAI Responses API.

## Decision

Keep selected same-file context disabled by default. The implementation is available behind `glide.sameFileContext`, but C2 did not improve the preregistered dependency score over the smaller C1 window and its result was worse for YAML. The experiment is too small to reject same-file selection generally.

Machine-readable results are summarized in [the remaining-objectives summary](2026-09-17-remaining-summary.json); captures and reviews are preserved in [the artifact index](2026-09-17-remaining-artifact-index.json).

## Implementation

The optional collector reads only the eligible active file, caps source inspection at 500,000 characters and selected text at 2,000 characters, ranks imports/declarations/YAML anchors using nearby identifiers, removes adjacent duplicates, limits concurrent work to two calls, and uses a 25 ms deadline. Cancellation and stale-document checks bracket collection. Related context is serialized in a separate prompt section and included in cache identity. No cross-file read, persistent index, embedding service, or new network destination was added.

The benchmark compared P0 with:

- C0: the existing full synthetic context;
- C1: an 8,000-character prefix and 2,000-character suffix;
- C2: C1 plus up to 2,000 selected same-file characters.

It used both cursor states from Go, TypeScript and Python far-helper families and a YAML far-anchor family, plus a JSON no-selection control. Three repetitions per arm produced 90 interleaved requests. All completed; no holdout case was queried.

| Arm | Reference/data matches | Dependency-family matches | Request p50 / p95 | Input / output tokens | Processed syntax valid |
| --- | ---: | ---: | ---: | ---: | ---: |
| C0 full | 26 / 30 | 20 / 24 | 1,517 / 2,706 ms | 68,319 / 261 | 28 / 30 |
| C1 small | 27 / 30 | 21 / 24 | 1,679 / 2,947 ms | 38,553 / 303 | 27 / 30 |
| C2 selected | 24 / 30 | 18 / 24 | 1,577 / 3,073 ms | 39,225 / 270 | 24 / 30 |

C1 minus C0 was +3.3 percentage points on the five-family primary proxy, with a descriptive 95% family bootstrap interval of -10 to +20 points. C2 minus C0 was -6.7 points, interval -40 to +20. Go and Python were 6/6 in every arm. TypeScript improved from 4/6 in C0 to 6/6 in C1/C2. YAML reference/data matches were 4/6, 3/6 and 0/6. The JSON control had equal parsed values in all 6 samples per arm even though exact strings varied.

The usage-priced estimate before cache-tier adjustment was $0.0302202 with no unknown samples; the full planning reservation was $0.23583525. The 25 ms collector has deterministic unit coverage, but this live measurement reports request latency rather than collector latency inside VS Code.

## Outcome

C1 used about 44% fewer aggregate input tokens than C0 and achieved a similar result in this narrow sample. That supports a future focused adjacent-window experiment, but the production 24,000/6,000 limits remain unchanged because this study did not represent broad editing contexts. C2 stays opt-in for further dogfood and targeted fixture work. The default sends only adjacent active-file context.
