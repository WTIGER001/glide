## Baseline and scope

The GL-02 prerequisite now preserves generated nested closing braces. Heuristic suffix-based stream termination is disabled: every arm waits for the server terminal status. Final cleanup uses a limited lexical check to distinguish generated closing delimiters from a prefix delimiter duplicated in the suffix. Uncertain substantial echoes are rejected. This trades some return coverage and potential early-stop savings for fewer corruptions and consistent terminal status/usage. Freeze this processor and client across all comparisons. Keep production prompt P0 unchanged until a supported winner passes the gates below.

Corpus remains `glide-synthetic-v1`, SHA-256 `a4859f9dcdfd87f7f05913d8fbc6c708914f016a4763d8e65ac214f6779463e0`: 112 development cases / 56 families, including Go, TypeScript, Python, YAML and JSON. The 56-case holdout is not used for screening. Of the development families, 52 are completion opportunities and four have conservative abstention labels. Related cursor states and repetitions are not independent samples.

The baseline check passed 104 unit tests, the VS Code 1.82 integration test, all 81 authored functional/alternative checks, and all 148 raw/processed completion syntax checks. All seven minimal regressions, including nested braces, pass. Four CRLF string changes remain semantically equivalent under the authored checks.

## Stages, hypotheses and selection rules

1. **Capability pilot:** exactly one synthetic P0 request (`go-closer-hole`), 96 output tokens, reasoning `none`. Stop if the endpoint rejects the contract. This pilot succeeded with a completed insertion and usage. Do not infer quality or typical latency from it.
2. **Prompt screen:** P0 current production prompt; P1 compact insertion contract; P2 P1 plus one independently authored Go example; P3 the same P2 instruction/example with AFTER before BEFORE. All use identical context, client, processor, 96-token limit and reasoning `none`. Hypothesis: stronger insertion instructions and an example improve the completion reference/data-match proxy and reduce malformed output without unacceptable latency or abstention changes. Run each of 112 development cases once per arm: 448 requests. Pair all four arms within each case/repetition; deterministic shuffled case order and balanced arm-position rotations reduce timing/order bias. Seed 17. This is exploratory screening, not a confirmatory significance test.
3. **Finalist confirmation:** retain P0 plus at most one screened candidate. Use at least three requests per development case, interleaved. Select a candidate only if it has higher completion reference/data matching, no new reproduced cleanup corruption, no material syntax/abstention regression after reviewing unmatched outputs, and no more than 20% degradation in completed-response p95 relative to P0. If differences are inconclusive, retain P0. Report paired source-family bootstrap intervals (2,000 resamples) as descriptive, not adjusted for selection or multiple comparisons. A positive interval alone does not prove semantic correctness or usability.
4. **Output-budget comparison:** keep the selected prompt fixed and compare B0 fixed96; B1 short48/block96; B2 short96/block160. Requested short/block mode comes only from current line context (blank line or trailing `{`/`:` => block); never use the removed answer or gold mode to choose the request cap. Record actual caps, assess categories separately, and retain B0 if the conditional policy provides no supported benefit. At least three repetitions are the default; respect the remaining session budget. Hypothesis: shorter caps reduce latency/waste while a higher block cap avoids incomplete blocks. Incomplete responses count as outcomes and earn no correct-abstention credit.
5. **Holdout confirmation:** only after a candidate is frozen on development. The runner requires a completed development finalist report with identical corpus, code hashes, endpoint, model and selected arm definitions, and at least three repetitions. Review holdout once. Do not modify prompts using its outputs. If no candidate warrants confirmation, record “no promotion” and preserve the unused holdout rather than spending it.

Do not test `low` reasoning or token-fragment reconstruction unless observed errors motivate a separate preregistered experiment and the remaining budget covers it. Do not replace Luna with a different model during this ticket.

## Measurements and adjudication

Report raw and processed reference/known-alternative matches, YAML/JSON parsed-value equality, nonempty processed return counts, abstention, incomplete/failure counts, completion lengths, known-good characters, request/first-text latency p50/p95, and usage/cost assumptions. Reference/data matching is the automated primary **proxy**, not full semantic accuracy. Report raw/processed syntax from offline replay. Run no novel generated program on the host. Review unmatched, nonempty outputs against cursor context and intended behavior; keep unresolved behavior labeled unverified. Record review decisions with case/arm/repetition and a reason. Do not silently enlarge the reference set during comparisons.

No automatic promotion. A prompt must pass the known insertion gates and show a defensible correctness/latency tradeoff to ship. “Retain P0; inconclusive” is valid. Even a prompt winner does not establish last-edit-to-display latency, human acceptance, or useful characters per minute. Those require GL-09/GL-11.

## Budget and reproducibility

Each planned run records source/corpus/prompt/request hashes, arm definitions, randomized order, actual output caps, endpoint/model/settings and the upfront estimate. It validates total requests and estimated cost before network access, saves every attempt, and never retries automatically. API transport failures stop the run; incomplete model output does not. Partial runs show unattempted counts and no paired comparison interval.

Track the **sum of reservations for all executed runs** against the session's $2 limit, including failed and cancelled attempts. Do not free reservation for missing usage. Rates checked in [official Luna model documentation](https://developers.openai.com/api/docs/models/gpt-5.6-luna): $0.20 input / $1.20 output per million tokens. The estimate reserves UTF-8 bytes plus 1,024 input overhead, a 1.25 input multiplier and full output caps; it is not a guaranteed provider billing ceiling. See the [Responses contract](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) and [GPT-5.6 guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6). Actual cached-token discounts and other adjustments are not available through the current aggregate usage parser.

Review reports use `npm run benchmark:experiment -- --replay PATH --syntax --out NEW_PATH`. Live planning uses `--phase pilot|screen|confirm|budgets|holdout`, `--hypothesis`, `--max-requests`, `--budget-usd`, `--input-price`, `--output-price`, and optional `--arms`, `--prompt`, `--cases`, `--repetitions`, `--seed`. Add `--execute` only with credentials and authorized remaining budget. Existing artifact paths are never overwritten. Holdout additionally requires `--frozen-config PATH`.

## Amendment before the restarted screen

The initial screen was deliberately stopped after 200 attempts (199 completed, one cancelled) when code review reproduced another boundary defect: a closer for an inner opener already present in the prefix was still required, while the suffix closed an outer opener. Its partial results remain in `gl07-screen-live.json`; do not pool them into the restarted comparison. Retain its full $0.2538466 reservation against the session cap. The corrective baseline now checks reconstructed delimiter balance before removing a prefix-owned closer; an already-balanced reconstruction stays unchanged. Go/TypeScript/JSON tests and the new `prefix-owned-inner-brace` gate pass. Validation: 107 unit tests, editor integration, all 81 authored checks, all 148 raw/processed syntax checks, and all eight minimal regressions.

Review also identified an invalid editor state in `json-crlf-typed`: its synthetic cursor falls between CR and LF. Exclude the entire `json-crlf` source family from the restarted screen and subsequent development confirmation/budget comparisons, preserving within-family treatment. This gives **110 cases / 55 families**, including 51 completion families and four abstention families. The corpus files and hash remain unchanged; selection is explicit in every run manifest. This exclusion is based on editor representability, not which prompt won that case. The 56 holdout cases are unchanged. Keep the initial full-screen data for audit, not prompt selection.

Some removed answers are underdetermined by visible context (for example, an empty-string fallback versus `"anonymous"`). Report those mismatches as unverified rather than proven wrong. This limitation strengthens the no-automatic-promotion rule; do not rewrite fixtures or gold answers mid-comparison.

## Decision before output-budget data collection

The completed restarted screen has 440/440 completed requests. P0/P1/P2/P3 have 33/31/30/25 reference-or-data matches out of 102 completion opportunities each, and 1/0/0/0 authored abstentions out of eight each. All descriptive family intervals include zero (P3's upper bound is zero). None satisfies the preregistered higher-match screen criterion; therefore retain P0, skip prompt-finalist confirmation and leave holdout untouched. This is an inconclusive quality comparison, not proof that compact prompts are worse: their latency and syntax results remain promising and should be reported.

No screen response reached 48 output tokens. The cap study is therefore an **exploratory repeated sensitivity check**, not a search for an already-observed truncation repair. Use P0 for B0/B1/B2 on 32 development cases from 16 source families, three repetitions per case/arm (288 requests). Choose families independently of observed scores: sort each language's eligible development families by SHA-256 of `gl07-budget-v1:` plus family ID; take eight Go families and two each TypeScript/Python/YAML/JSON. Both cursor states are retained. The selected families are go-contains, go-escape, go-join, go-last, go-divide, go-unicode, go-struct, go-sum, ts-template, ts-optional, py-fstring, py-tabs, yaml-unicode, yaml-quoted, json-boolean, json-escape. This fixed subset contains no abstention families; make no new abstention claim from it. The full development screen supplies the abstention observations.

Do not ship a cap change from a small or inconclusive result. Retain fixed96 unless the repeated study shows a supported quality/latency benefit and a later full development/holdout validation is justified. This narrows the original all-case budget-stage proposal before collecting its data, given the nonbinding caps and the unresolved corpus ambiguity; it does not change or omit prompt-screen outcomes.

Supplemental offline review compares Go formatting, Python ASTs, and emitted TypeScript JavaScript against authored references to identify representation-only misses. It never executes generated programs and does not alter the frozen primary metric. TypeScript equality does not establish static type correctness. Store this separately with script/source hashes; unresolved behavior remains unverified.
