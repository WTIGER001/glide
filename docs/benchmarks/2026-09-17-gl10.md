# GL-10: Responses prompt caching

Session date: 2026-09-17 America/New_York.

## Decision

Prompt caching is evaluated and no explicit cache key or breakpoint is added to production. Automatic server caching already activated for eligible long repeated prompts. It reduced the estimated cache-adjusted cost in the synthetic context run, but did not produce a latency benefit in this small, interleaved sample. Normal editor prompts can be shorter and change continually, so the benchmark result must not be projected to ordinary usage.

## API support and implementation

The Responses client now parses cached input, cache-write input and reasoning-output token details. Capture and replay schemas preserve them. The experiment client can send a benchmark-only `prompt_cache_key`; production does not send stable user or repository identifiers.

OpenAI documents a 1,024-token minimum reusable prefix for GPT-5.6 prompt caching, a 1.25x write rate, a 0.1x read rate, usage detail fields, and a cache lifetime of at least 30 minutes. `store:false` controls response storage and is distinct from prompt-cache handling. See the [GPT-5.6 Luna model page](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), and [Responses create reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create).

## Observed usage

The 90-request GL-08 run recorded 146,097 input tokens, including 95,130 cache-read tokens and 47,565 cache-write tokens; 3,402 tokens were outside those two subsets. Each arm had 8 writes and 16 reads among its 30 requests. No cache fields appeared in the shorter 72-request GL-07b run.

| Arm | Read / write tokens | Read p50 / p95 | Write p50 / p95 |
| --- | ---: | ---: | ---: |
| C0 | 44,790 / 22,395 | 1,738 / 2,706 ms | 1,363 / 1,763 ms |
| C1 | 24,946 / 12,473 | 1,751 / 2,473 ms | 1,255 / 1,867 ms |
| C2 | 25,394 / 12,697 | 1,746 / 3,073 ms | 1,295 / 1,855 ms |

Using the experiment's $0.20 input and $1.20 output rates, plus the documented 1.25x/0.1x cache multipliers, the cache-adjusted estimate is $0.01547505 versus $0.03022020 if every input token were charged at the uncached rate. This is an estimate, not an invoice. Cache reads were not faster than writes in this sample, and arms differ in prompt length and output behavior.

## Outcome

Keep automatic provider behavior and expose accurate usage. Do not add filler, retain old source snapshots, reorder the insertion prompt solely for cacheability, or introduce durable cache identifiers. Revisit only with real editor traces showing enough eligible tokens and a controlled cold/warm latency comparison.
