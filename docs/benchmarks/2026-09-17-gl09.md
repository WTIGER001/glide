# GL-09: timing and trigger policy

Session date: 2026-09-17 America/New_York.

## Decision

Retain the fixed 175 ms automatic debounce. Explicit inline-completion invocation now bypasses that delay and the automatic-only empty-line/completed-closer suppressions, while preserving workspace trust, sensitive-file, credential, endpoint, selection and long-line guards.

## Machine evidence

Replaying the same 29 deterministic typing opportunities at 75, 175 and 300 ms produced 18, 13 and 8 modeled requests. With the trace's fixed one-second provider delay, all three policies returned before the next edit six times. These synthetic traces show request-volume sensitivity; they cannot measure usefulness or distraction, so they do not justify changing the default.

Statistics schema V3 separately records automatic and explicit opportunities, active editing time, request/cancellation volume, returned and accepted characters, and accepted characters per active minute. Migration from V2 preserves previous aggregate data. Storage remains source-free.

Unit tests cover explicit trigger behavior and stale cancellation. Native VS Code integration tests cover explicit multiline acceptance, disable/enable, protected `.env.local`, hiding a suggestion, and editing during a delayed request. The same suite passed in VS Code 1.82.0 and current stable 1.138.0.

## Human gate

Five complete coding sessions, accepted characters per active minute, and subjective distraction still require real editor use. Automated traces and command-driven editor tests cannot supply that evidence. The release candidate keeps the stable fixed policy until those sessions support a change.
